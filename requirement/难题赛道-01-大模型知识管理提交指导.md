## 参赛作品提交规范

### 1. 提交内容

参赛作品统一提交至 `work/` 目录，目录结构不限。

作品形式不限，包括但不限于：

- CLI 工具
- Agent
- Skill
- MCP Server
- Web 服务
- Extension
- Docker 应用
- 其他自动化工具

本赛题中，参赛作品需要实现的是：**{内容}**。

------

### 2. 平台提供的材料

评测平台会提供llm-wiki的题目、题目所需的原始文件等材料，参赛选手不需要提交这些内容。

平台提供路径如下：

```text
├── /app/code/judge-assets/01_01_llm_wiki/
│   ├── question/group-*.md
│   ├── docs/
│   │   ├── 00_业务总结/
│   │   ├── 01_技术总结/
│   │   ├── 02_环境信息/
│   │   ├── 03_学习材料/
│   │   ├── 04_常用命令/
│   │   ├── 05_需求设计/
│   │   ├── 06_日常办公/
│   │   ├── 07_其他/
│   │   └── 99_mock_system_dir/
│   └── Permission.json

```

参赛作品应在提交作品的INSTRUCTION.md中注意指明，避免用例执行不完整。

------

### 3. 必须包含文件

参赛作品根目录至少包含以下内容：

| 路径                                    | 类型 | 要求 | 说明                                                         |
| --------------------------------------- | ---- | ---- | ------------------------------------------------------------ |
| /INSTRUCTION.md                         | 文件 | 必选 | 作品运行的入口，平台通过加载该Markdown执行作品运行过程，验证用例通过性 |
| /work                                   | 目录 | 必选 | 用于存放作品可运行交付件的目录，可以存放Skill/Agent/MCP等    |
| /work/skills/{your-skill-name}/SKILL.md | 文件 | 可选 | 如提交Skill，按Skill规范存放Skill的目录和入口文件            |
| /work/skills/{your-subagent-name}.md    | 文件 | 可选 | 如提交subagent，在skills目录下存放，并在INSTRUCTION.md中使用 |
| /result                                 | 目录 | 必选 | 用于存放作品自验证的记录                                     |
| /result/screenshot                      | 目录 | 可选 | 存放作品运行成功、用例通过的截图文件                         |
| /result/output.md                       | 文件 | 必选 | 记录作品运行成功的输出信息，如有图片，以Markdown规范引用     |
| /logs                                   | 目录 | 必选 | 用于存放推理过程的记录和交互信息                             |
| /logs/interaction.md                    | 文件 | 必选 | 记录选手与作品人工交互的记录，如全程无干预，留空             |
| /logs/trace                             | 目录 | 必选 | 用于存放推理过程日志                                         |
| /problem_statement                      | 目录 | 可选 | 对于赛道一，难题赛道，如选择自行出题，此目录必须存在，目录内以PROBLEM.md主文件描述自行出题的题目要求 |

其中：

- `INSTRUCTION.md`：裁判执行说明书，用于指导自动评测系统部署、启动、执行参赛作品并获取修复结果。

------

### 4. INSTRUCTION.md 编写要求

自动评测系统将依据 `INSTRUCTION.md` 执行参赛作品。

其中：

- `INSTRUCTION.md`：裁判执行说明书，用于指导自动评测系统部署、启动、执行参赛作品并获取修复结果。

### 4. INSTRUCTION.md 编写要求

自动评测系统将依据 `INSTRUCTION.md` 执行参赛作品。

`INSTRUCTION.md` 至少应包含以下内容：

#### 4.1 环境准备

说明参赛作品运行所需的环境准备步骤，包括但不限于：

- 依赖安装
- 编译构建
- 服务启动
- Docker 环境准备
- MCP、Skill、Agent 等组件安装
- 启动执行前请注意，需指明赛题所在目录，llm-wiki的公开用例只作为参考，不作为实际判例。所有用例归档在预置目录/app/code/judge-assets/01_01_llm_wiki/中，包括题目和原始文件，目录结构与公开代码仓下目录一致

所有步骤应能够自动完成，不得依赖人工操作。

#### 4.2 执行方式

说明如何执行参赛作品，包括但不限于：

- 启动命令
- 执行命令
- 参数说明
- 调用方式
- 执行顺序

#### 4.3 执行完成判定

说明如何判断参赛作品执行完成，例如：

- 命令退出
- 服务返回完成状态
- 指定文件生成
- 指定接口返回成功

#### 4.4 修复结果获取方式

说明自动评测系统如何获取最终修复结果，包括但不限于：

- 修复后的工程位置
- 输出文件位置
- 日志文件位置
- 报告文件位置
- 其他需要评测的交付件

------

### 5. 自动评测流程

自动评测系统将按照以下流程执行：

1. 阅读 `INSTRUCTION.md`
2. 按照说明完成环境准备
3. 准备平台提供的 LLM-WIKI 项目材料
   ...
   ...

------

### 6. 注意事项

以下情况将导致作品无法完成自动评测：

- 缺少 `INSTRUCTION.md`
- `INSTRUCTION.md` 无法指导自动执行
- 执行过程需要人工交互
- 无法判断执行完成
- 无法获取修复后的工程
- 修复后的工程无法构建
- 修改了 REST API 契约
- 未提供方案说明或验证方案
- 包含 Skill 则路径必须符合 `work/skills/{your-skill-name}/SKILL.md` 规范
